# 첨부 이미지 기반 4종 마스크 재디자인 계획

## 목표

사용자가 첨부한 나비·나뭇잎·전구·구름 이미지를 시각 기준으로 삼아, 마스크 선택 아이콘과 워드 클라우드 외곽선을 같은 조형 언어로 다시 그린다. 구현과 로컬 브라우저 검증까지만 진행하고, 사용자 승인 전에는 커밋·푸시·배포하지 않는다.

## 프런트엔드 디자인 기준

- **Visual thesis:** 흑백 종이 오리기 도안처럼 선명하고 단순하며, 초등학생이 윤곽만 보고도 즉시 이름을 말할 수 있는 친근한 실루엣.
- **Content plan:** 캔버스 외곽선이 사물의 전체 형태를 설명하고, 내부선은 더듬이·잎맥·전구 소켓처럼 인식에 꼭 필요한 특징만 보조하며, 설정 아이콘은 같은 형태를 축소해서 보여 준다.
- **Interaction thesis:** 선택 즉시 다시 그리는 기존 동작과 선택 강조를 유지한다. 새 장식 애니메이션은 추가하지 않고, 마스크 모양 자체가 가장 강한 시각 신호가 되게 한다.

## 첨부 이미지 해석

### 나비

- 좌우 대칭을 엄격히 유지한다.
- 위 날개는 길고 넓게 벌어지고, 옆면은 깊게 안으로 들어간 뒤 둥근 아래 날개로 이어진다.
- 아래 중앙에는 얕은 V자 홈을 두어 양쪽 아래 날개가 분리되어 보이게 한다.
- 중앙에는 작은 머리와 두 갈래 더듬이만 세부선으로 둔다.

### 나뭇잎

- 한 장의 잎을 오른쪽 위로 향하는 대각선 형태로 배치한다.
- 외곽은 단순 타원이 아니라 양쪽에 5~7개의 부드러운 톱니를 가진 긴 잎몸으로 만든다.
- 왼쪽 아래 잎자루에서 오른쪽 위 끝까지 중앙 잎맥을 연결한다.
- 곁맥은 5~6개만 사용해 참고 이미지의 특징을 살리되 워드 가독성을 해치지 않게 한다.

### 전구

- 전구 윗부분은 거의 원형인 큰 돔으로 만들고, 아래로 갈수록 부드럽게 좁아져 소켓에 연결되게 한다.
- 소켓은 세 줄의 수평선과 짧은 둥근 끝으로 표현한다.
- 위·좌우 대각선에 짧은 빛살 7개를 세부선으로 배치한다.
- 단어 배치 영역에는 전구 본체와 소켓만 포함하고 빛살에는 단어를 배치하지 않는다.

### 구름

- 큰 왼쪽/중앙 돔 하나, 작은 오른쪽 위 돔 하나, 중간 크기의 오른쪽 돔 하나로 단순화한다.
- 왼쪽 끝과 오른쪽 끝은 둥글고, 밑선은 거의 평평하게 만든다.
- 참고 이미지처럼 봉우리 사이 골을 얕게 하여 통통하고 안정적인 실루엣을 만든다.

## 구현 순서

1. 네 마스크의 물체별 핵심 좌표를 검증하는 회귀 테스트를 먼저 작성한다.
2. `app/lib/masks.mjs`의 외곽선과 내부 배치 판정을 같은 경로로 맞춘다.
3. `traceMaskDetail`에 나비 더듬이, 잎맥, 전구 소켓·빛살을 반영한다.
4. `app/components/QuickSettings.tsx`의 네 아이콘을 같은 비례로 다시 그린다.
5. 업데이트 내역에 첨부 이미지 기반 재디자인을 기록한다.
6. 단위 테스트·렌더링 테스트·린트·정적 빌드를 실행한다.
7. 데스크톱과 390×812에서 네 마스크를 실제 렌더링하고 검토용 화면을 준비한다.
8. 사용자 승인 전에는 커밋·푸시·배포하지 않는다.

## 승인 기준

- 나비는 네 날개, 깊은 옆 허리, 아래 V 홈이 보인다.
- 나뭇잎은 뾰족한 끝, 톱니 가장자리, 잎자루와 대각 잎맥이 보인다.
- 전구는 둥근 전구부, 좁아지는 목, 소켓 세 줄과 빛살이 보인다.
- 구름은 세 개의 둥근 봉우리와 평평한 밑선이 보인다.
- 100개 단어가 네 외곽선 안에 모두 배치된다.
- 390×812에서 가로 넘침 없이 아이콘과 마스크가 구분된다.
